# Droide Package Registry

`droide-package-sources-v1.json` is the reviewed source authority. The Android runtime catalog is generated by `tools/compile_droide_package_catalog.py`.

Pending packages can be researched in bulk with:

```bash
python3 tools/harvest_droide_package_catalog.py \
  --input registry/droide-package-sources-v1.json \
  --output /tmp/droide-package-harvest.json
```

For deterministic/offline validation use the checked-in parser fixtures:

```bash
python3 tools/harvest_droide_package_catalog.py \
  --input registry/droide-package-sources-v1.json \
  --fixtures tools/fixtures/package-harvest-v1.json \
  --output /tmp/droide-package-harvest.json
```

The harvester is intentionally review-only. It never changes `PENDING` to `CERTIFIED`; generated recipes must pass provider runtime, integrity, archive, health, ownership, rollback and Android runtime gates before promotion.

GitHub single-command recipes may additionally declare `exactAssetName` when token/format matching is not unique. Interpreted RAW recipes require an exact asset name and may declare bounded `interpreterArgs`; their payload bytes stay non-executable data and must be launched by an explicitly managed interpreter. Native RAW recipes continue through ARM64 ELF admission and cannot declare interpreter metadata.

GitHub recipes may alternatively declare `assetNameTemplate` when an upstream publishes a stable versioned filename. It is mutually exclusive with `exactAssetName`, must contain exactly one `{version}` placeholder, and is expanded only after the stable release tag has been normalized to the exact version. Interpreted WHOLE_TREE recipes may also use `{version}` inside reviewed tree paths and bounded interpreter arguments. The generic interpreter argument budget is capped at 12 entries; unknown placeholders remain fail-closed.
